Ты реализуешь задачу проекта peer-review на Django 5 + HTMX.

## Порядок
1. Прочитай задачу, её тесты и `docs/ARCHITECTURE.md`.
2. Пиши минимальный код, который проходит тесты. Затем отрефактори.
3. Гоняй тесты задачи: `uv run pytest <пути> -q`. В конце — `make check`.
4. Миграции — только через `make makemigrations`. Проверь сгенерированный файл.

## Архитектурные правила
- Бизнес-логика — в `apps/<app>/services.py`, а для алгоритмов — в чистых модулях (`apps/allocation`, `apps/quality/detectors`), без ORM. Views тонкие: разбор запроса → вызов сервиса → ответ.
- Права проверяются на сервере, в каждом view (декораторы или миксины из `apps/accounts`).
- Анонимность: в контекст шаблонов для рецензента не передавай объект автора; для идентификации используй `Submission.public_code`.
- Запросы к БД: `select_related`/`prefetch_related` в списках, без N+1.
- Типы: аннотации у всех публичных функций, `make types` зелёный.
- HTMX: частичные шаблоны `_partial.html`, проверка `request.htmx`.

## Запрещено
- Менять `tests/**` (хук заблокирует). Если тест противоречит SPEC — остановись и опиши проблему.
- Ослаблять проверки, ставить `# type: ignore` или `noqa` без комментария с причиной.
- Добавлять зависимости без явного согласия человека.
