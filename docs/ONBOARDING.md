# Онбординг второго участника

## 1. Развернуть проект (≈10 минут)
Нужны: git, Python 3.12+, make, Node.js (для Playwright MCP), Claude Code. Docker не обязателен.

```bash
git clone https://github.com/DANIK20060731/TP_Project_3kurs.git
cd TP_Project_3kurs
pip install --user uv          # или https://docs.astral.sh/uv/ ; проверить: uv --version
make install                   # зависимости + Chromium для e2e + pre-commit
make check                     # должно быть зелёным
make seed && make run          # http://localhost:8000, учётки — в apps/core/management/commands/seed_demo.py
```
Если `uv` не нашёлся в PATH — добавьте каталог из `python3 -m site --user-base`/bin в PATH или вызывайте `make <цель> UV=/путь/к/uv`.
На Windows хуки требуют `python3` в PATH (или WSL).

## 2. Запустить агента
```bash
claude        # в корне репозитория
```
При первом запуске Claude Code спросит, доверять ли проекту и MCP-серверам из `.mcp.json` — разрешите `playwright` (`postgres` нужен только с Docker).
Вставьте стартовый промпт из раздела 3.

## 4. Как мы работаем вдвоём
- Владение: **участник 1** — `allocation`, `reviews`, `quality`; **участник 2** — `accounts`, `courses`, `assignments`, `submissions`, `notifications`, `analytics`, UI.
- Начало: участник 2 — **T-001** (кастомный User; он должен появиться раньше любых других миграций), затем T-002 → T-003 → T-004 → T-005. Участник 1 параллельно — T-006 и T-011 (не зависят от моделей).
- Одна задача = одна ветка `feat/T-xxx-slug` = один PR в `main`. Merge — после зелёного CI и одобрения второго участника.
- Перед новой задачей: `git switch main && git pull`, чтобы получить чужие изменения (особенно миграции).
- Не запускайте две сессии агента в одной папке — они перетирают друг другу файлы. Нужна вторая параллельно — `git worktree add ../tp-T-xxx -b feat/T-xxx-slug`.
- Изменения харнесса (`.claude/settings.json`, `.claude/hooks/`) делает только человек: `touch .claude/.state/harness-unlock`, правка, затем `rm` этого файла; изменение — отдельным PR, о котором договорились оба.
