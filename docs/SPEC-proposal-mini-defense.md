# Предложение к SPEC — проверка понимания

Статус: на согласовании обоих участников. После согласования добавить роль преподавателя
в §1, требования FR-9 в §2, сценарии расширения в §4 и ограничения в §5
[действующего SPEC](SPEC.md). Нумерация исходных сценариев 1–6 сохраняется.

## §1. Дополнение к роли преподавателя

Владелец курса готовит и проводит устную мини-защиту, утверждает вопросы и фиксирует
индивидуальные результаты. В первой версии карточки, вопросы, ориентиры и результаты
доступны только владельцу курса. Публикация студентам рассматривается отдельно.

## §2. FR-9. Проверка понимания

- **FR-9.1** С дедлайна рецензий преподаватель может открыть работу, действующие отправленные рецензии и создать проверку конкретного автора. Для командной работы выбирается один соавтор. Первый рабочий этап поддерживает ручные вопросы без внешнего ИИ.
- **FR-9.2** У защиты отдельные состояния «подготовка», «проведение» и «завершено». В подготовке преподаватель редактирует вопросы. При начале набор фиксируется. Для завершения нужен хотя бы один заданный вопрос и результат по каждому заданному. Для незаданного вопроса результата нет.
- **FR-9.3** Система может предложить 5–10 вопросов автору по конкретной работе и её действующим отправленным рецензиям. Каждое предложение содержит проверяемый фрагмент источника, цель и ориентиры ответа. Преподаватель выбирает, редактирует и утверждает вопросы. При сбое или отсутствии настройки доступен ручной режим.
- **FR-9.4** Владелец фиксирует результат и короткий комментарий. Результат хранится отдельно от итоговой оценки работы и не меняет её. Защита не добавляет фазу задания. Служебные данные и личности участников недоступны студентам, изменения требуют POST с CSRF и объектной проверки прав.
- **FR-9.5** Следующий этап добавляет проверку конкретного рецензента по отправленной рецензии. Старт возможен с карточки работы или от флага качества. Флаг помогает выбрать материал для проверки. Действия модерации и пересчёт оценки остаются в существующем процессе.
- **FR-9.6** Внешнему сервису передаётся ограниченный контекст выбранной работы. Прямые идентификаторы из БД не добавляются. Титульные страницы и возможные персональные данные в материалах обрабатываются отдельно. Если контекст нельзя подготовить по согласованным правилам, доступен ручной режим.

## §4. Сценарии расширения

- Авторская защита: сдача → рецензии → предложения вопросов → утверждение преподавателем → устная проверка → отдельный результат на дашборде.
- Ручной режим: без ключа или при сбое преподаватель задаёт собственные вопросы и завершает защиту.
- Защита рецензента: по конкретной отправленной рецензии преподаватель просит обосновать оценку или замечание и сохраняет отдельный результат.

Исходные сценарии покрывает T-015, сценарии расширения покрывает T-025.
Первую версию с вопросами ИИ для автора составляют T-020–T-023. T-024 можно отложить
при ограничении сроков. Дата выпуска подлежит согласованию.

## §5. Границы расширения

В первую версию входят ручная проверка и предложения для преподавателя. За её рамками
остаются распознавание ИИ-текста, автоматическая оценка устного ответа, обучение
переписыванию рецензий, OCR, архивы, LMS, несколько поставщиков ИИ и большая база знаний.
