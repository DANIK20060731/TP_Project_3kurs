# SPEC — Платформа peer-review студенческих работ

Источник истины для требований. Изменения — только по согласованию обоих участников.
Формулировка темы (от преподавателя): студенты загружают работы, система анонимно распределяет их на рецензирование по рубрике, преподаватель видит статистику и конфликты оценок. Ядро темы — алгоритм распределения без взаимности и без самого себя, рубрики с критериями и шкалами, дедлайны с напоминаниями, детектор «халтурных» рецензий (слишком коротких или одинаковых под копирку).

## 1. Роли
| Роль | Может |
|---|---|
| Студент | видеть свои курсы; сдавать работу (одну или в команде); рецензировать назначенные работы; видеть полученные рецензии (анонимно) и итоговую оценку |
| Преподаватель | создавать курсы и задания, рубрики, дедлайны; запускать распределение; видеть всё неанонимно; статистику, конфликты, флаги халтуры; переназначать рецензии; выставлять итог |
| Администратор | Django admin |

## 2. Функциональные требования

### FR-1. Учётные записи и курсы
- FR-1.1 Регистрация и вход; роль student/teacher (преподавателя назначает администратор).
- FR-1.2 Преподаватель создаёт курс и группы, приглашает студентов по коду курса.
- FR-1.3 Студент записывается на курс по коду.

### FR-2. Задания и рубрики
- FR-2.1 Задание: название, описание, допустимые форматы файлов, максимальный размер, индивидуальное или командное, `k` — число рецензий на работу.
- FR-2.2 Дедлайны: сдачи работ (`submission_deadline`) и рецензий (`review_deadline`, всегда позже).
- FR-2.3 Рубрика: ≥ 1 критериев; у критерия — название, описание, вес, шкала. Шкала — набор уровней (балл + описание уровня, например 0 «не выполнено» … 3 «отлично»).
- FR-2.4 Рубрику можно скопировать из другого задания. После старта рецензирования рубрика заморожена.
- FR-2.5 Пороги детектора халтуры настраиваются в задании (значения по умолчанию — в `apps/quality/CLAUDE.md`).

### FR-3. Сдача работ
- FR-3.1 Студент загружает файл (и/или ссылку) до дедлайна; до дедлайна можно заменить файл, хранится последняя версия.
- FR-3.2 Командная работа: один участник сдаёт и указывает соавторов из курса; соавторы видят работу.
- FR-3.3 После дедлайна сдача и замена запрещены (проверка на сервере).

### FR-4. Распределение
- FR-4.1 После дедлайна сдачи преподаватель запускает распределение (позже — автоматически).
- FR-4.2 Ограничения: нет самоназначения; нет взаимных пар; соавторы не рецензируют друг друга и одну и ту же работу; ровно `k` рецензентов на работу; нагрузка отличается не больше чем на 1. Рецензируют только студенты, сдавшие работу.
- FR-4.3 Невыполнимая конфигурация (например, 2 сдавших при k=1) → понятное сообщение преподавателю с причиной.
- FR-4.4 Распределение воспроизводимо (seed сохраняется) и атомарно (всё или ничего).
- FR-4.5 Преподаватель может вручную переназначить рецензию; инварианты проверяются и при этом.

### FR-5. Рецензирование
- FR-5.1 Студент видит список назначенных работ под анонимными кодами, в случайном порядке.
- FR-5.2 Рецензия — выбор уровня по каждому критерию + общий комментарий (+ комментарий к критерию, опционально). Черновик сохраняется (HTMX, автосохранение).
- FR-5.3 После отправки и до дедлайна рецензию можно редактировать; после дедлайна — нельзя.
- FR-5.4 Автор видит полученные рецензии без имён рецензентов после дедлайна рецензий.

### FR-6. Качество рецензий
- FR-6.1 Детекторы: слишком короткая, копипаста (внутри рецензента и между рецензентами), одинаковые баллы по всем критериям, слишком быстрая.
- FR-6.2 Флаги видит только преподаватель, с причиной. Преподаватель может отклонить флаг или аннулировать рецензию.

### FR-7. Аналитика и конфликты
- FR-7.1 Дашборд задания: сдано/не сдано, рецензий выполнено/просрочено, распределение итоговых баллов.
- FR-7.2 Конфликт оценок: разброс баллов рецензентов по работе выше порога (по умолчанию max−min ≥ 40% шкалы) → работа помечена, преподаватель видит рецензии рядом.
- FR-7.3 Рецензент-выброс: систематическое отклонение его оценок от медианы других рецензентов.
- FR-7.4 Итоговая оценка работы — медиана взвешенных баллов рецензентов; преподаватель может переопределить.
- FR-7.5 Экспорт оценок в CSV.

### FR-8. Напоминания
- FR-8.1 Email за 24 ч и за 2 ч до дедлайна сдачи — тем, кто не сдал; до дедлайна рецензий — тем, у кого есть незавершённые рецензии.
- FR-8.2 Уведомление о назначении рецензий и о получении рецензий.
- FR-8.3 Повторно одно и то же напоминание не отправляется (идемпотентность).

## 3. Нефункциональные требования
- NFR-1 Анонимность — см. инварианты в `CLAUDE.md`. Покрыта тестами и аудитом.
- NFR-2 Распределение для 300 работ при k=3 — меньше 2 с.
- NFR-3 Покрытие тестами ≥ 85%, ядро (allocation, quality) ≥ 95%.
- NFR-4 Безопасность: CSRF, права в каждом view, проверка типа и размера файлов, без IDOR.
- NFR-5 Интерфейс на русском, работает на мобильном (адаптивная вёрстка).

## 4. Ключевые сценарии (для e2e)
1. Преподаватель создаёт курс → задание с рубрикой из 3 критериев, k=3 → студенты записываются.
2. 6 студентов сдают работы (одна командная из 2 человек) → дедлайн → преподаватель запускает распределение → у каждого 3 работы, инварианты соблюдены.
3. Студент открывает рецензию → выставляет уровни → черновик сохраняется → отправляет. Имя автора нигде не видно.
4. Один студент пишет «норм» и ставит всем критериям одинаковый балл → преподаватель видит флаги.
5. По одной работе оценки 1 и 3 из 3 → преподаватель видит конфликт и выставляет итог.
6. Автор после дедлайна рецензий видит рецензии без имён и итоговую оценку.

## 5. Вне рамок курсовой
Интеграция с LMS (Moodle), антиплагиат работ, мобильные приложения, SSO вуза.
