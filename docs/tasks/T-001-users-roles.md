# T-001: Пользователи и роли

- Статус: done
- Владелец: участник 2
- Зависимости: —
- Требования: FR-1.1, NFR-4

## Цель
Кастомная модель пользователя с ролью (student/teacher), вход и выход, базовые проверки прав, которыми будут пользоваться все остальные приложения.

## Критерии приёмки
- [x] **AC-1** Given чистая БД, When выполняется `migrate`, Then `AUTH_USER_MODEL = "accounts.User"` и у пользователя есть поле `role` со значениями `student`/`teacher`, по умолчанию `student`.
- [x] **AC-2** Given гость, When он регистрируется (username, email, пароль), Then создаётся пользователь с ролью `student` и выполняется вход.
- [x] **AC-3** Given зарегистрированный пользователь, When он вводит верные данные на `/accounts/login/`, Then попадает на главную. При неверных данных видит ошибку без раскрытия, существует ли логин.
- [x] **AC-4** Given декоратор/миксин `teacher_required`, When его view открывает студент, Then 403. Когда открывает преподаватель — 200. Гость — редирект на логин.
- [x] **AC-5** Given админка, When администратор меняет роль пользователя, Then изменение сохраняется (роль преподавателя студент сам себе выставить не может).
- [x] **AC-6** `seed_demo` создаёт `teacher` с ролью `teacher`, студентов — с ролью `student`.

## Пользовательский сценарий
1. Гость открывает главную → «Регистрация» → заполняет форму → оказывается на главной под своим именем.
2. Выход → вход → главная.

## Технические заметки
- **Важно:** кастомная модель должна появиться до первой миграции других приложений (`AbstractUser` + `role`). Сейчас в проекте нет миграций, кроме встроенных; удалите локальный `db.sqlite3` перед `migrate`.
- Права — в `apps/accounts/permissions.py` (декоратор и миксин), чтобы ими пользовались все приложения.
- Обновить `tests/factories.py`: `UserFactory`, `TeacherFactory`.
