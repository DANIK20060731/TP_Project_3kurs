# T-002: Курсы и запись по коду

- Статус: in-progress
- Владелец: участник 2
- Зависимости: T-001, T-016
- Требования: FR-1.2, FR-1.3

## Цель
Преподаватель создаёт курс и получает код приглашения; студенты записываются по коду.

## Критерии приёмки
- [ ] **AC-1** Given преподаватель, When он создаёт курс (название, описание), Then курс сохраняется с уникальным 8-символьным `invite_code` из алфавита без похожих символов (без `0 O 1 I L`), а преподаватель становится его владельцем.
- [ ] **AC-2** Given владелец курса, When он добавляет группу с номером из 4 цифр (например, `4231`), Then группа появляется в курсе. Номер не из 4 цифр или повтор номера в том же курсе → ошибка формы (UniqueConstraint `course + number`). В разных курсах номера могут совпадать.
- [ ] **AC-3** Given студент, верный код и курс с группами, When он вводит код и выбирает свою группу на странице «Записаться», Then создаётся `Enrollment(course, student, group)`, курс появляется в «Мои курсы» с номером группы. Код вводится без учёта регистра, пробелы по краям отбрасываются. Если у курса нет групп — запись без группы; если группы есть — выбор обязателен.
- [ ] **AC-4** (негативный) Повторная запись не создаёт дубликат (UniqueConstraint `course + student`), пользователь видит сообщение «Вы уже записаны».
- [ ] **AC-5** (негативный) Неверный код → ошибка формы, без 500. Группа другого курса, подставленная в POST, → ошибка формы, запись не создаётся.
- [ ] **AC-6** (права) Студент не может открыть страницу управления курсом (403), чужой преподаватель — тоже (403). Записываются только студенты: преподаватель на «Записаться» получает 403.
- [ ] **AC-7** Преподаватель видит список записанных студентов своего курса, сгруппированный по группам (и «Без группы»), и может перевести студента в другую группу этого же курса. Перевод в группу чужого курса или студента чужого курса → 404/ошибка формы, без IDOR.
- [ ] **AC-8** Преподаватель видит список своих курсов с кодом приглашения; код виден только владельцу курса.

## Пользовательский сценарий
1. Преподаватель → «Создать курс» → видит код → добавляет группы 4231 и 4232.
2. Студент → «Записаться» → вводит код (в нижнем регистре) → выбирает группу 4231 → курс в «Мои курсы» с номером группы.
3. Преподаватель → курс → видит студента в группе 4231 → переводит в 4232.

## Технические заметки
- Модели `Course(owner, title, description, invite_code)`, `Group(course, number)`, `Enrollment(course, student, group: null, created_at)` — через `/model`. `Group.number` — `CharField(max_length=4)` с валидатором `^[0-9]{4}\Z` — только ASCII-цифры (в Python `\d` пропускает и Unicode-цифры, например `４２３１`); строка, чтобы сохранить ведущие нули.
- Целостность: группа в `Enrollment` принадлежит тому же курсу — проверка в сервисе и в форме (queryset групп курса).
- Права — через `apps/accounts/permissions.py`; объекты курса берутся из queryset, отфильтрованного по владельцу/студенту.
- Курсы в URL — по pk (курсы не анонимны); `invite_code` в URL не попадает.
- Шаблоны — на базе T-016 (`base.html`, классы из `app.css`, `_form_fields.html`, сообщения через `messages`).
- Вне рамок: отписка от курса, удаление курса и групп, смена кода приглашения.
- Генерация кода — `secrets`, с повтором при коллизии; тест на коллизию — через monkeypatch.
