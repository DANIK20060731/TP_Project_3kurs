# T-003: Задания и дедлайны

- Статус: done
- Владелец: участник 2
- Зависимости: T-002
- Требования: FR-2.1, FR-2.2

## Цель
Преподаватель создаёт задание в курсе с двумя дедлайнами и параметрами рецензирования.

## Критерии приёмки
- [x] **AC-1** Given преподаватель курса, When он создаёт задание (название, описание, форматы файлов, макс. размер МБ, тип: индивидуальное/командное, `reviews_per_submission` k ≥ 1, `submission_deadline`, `review_deadline`), Then задание сохраняется и видно студентам курса.
- [x] **AC-2** (негативный) `review_deadline` ≤ `submission_deadline` → ошибка валидации; ограничение продублировано `CheckConstraint`.
- [x] **AC-3** (негативный) k < 1 или k > 10 → ошибка валидации.
- [x] **AC-4** У задания есть вычисляемая фаза: `submission` (до дедлайна сдачи) → `allocation` (после дедлайна сдачи, до распределения) → `review` → `closed` (после дедлайна рецензий). Тест с `freezegun` на каждую границу.
- [x] **AC-5** (права) Студент не может создать или изменить задание (403); студент другого курса и незаписанный студент не видят задание и его курс (404 — одинаково для чужого и несуществующего, см. ARCHITECTURE «403 и 404»); чужой преподаватель не может изменить задание (403).
- [x] **AC-6** Given владелец курса, When он редактирует задание, Then изменения разрешены по фазам (проверка в сервисе, не только в форме):
  - фаза `submission` — меняется всё; новый `submission_deadline` должен быть в будущем;
  - после `submission_deadline` — заморожены тип, форматы, размер и `submission_deadline`; `review_deadline` можно перенести, пока он не наступил; новое значение должно быть позже и текущего момента, и `submission_deadline`;
  - после распределения (`allocated_at` задан) — дополнительно заморожен k;
  - фаза `closed` — меняются только название и описание.
  Попытка изменить замороженное поле → ошибка формы с понятным текстом, данные не меняются.
- [x] **AC-7** Given студент курса, When он открывает курс в «Мои курсы», Then видит список заданий курса с дедлайнами и фазой на русском («Сдача работ», «Распределение», «Рецензирование», «Завершено»); владелец видит задания на странице управления курсом и ссылку «Создать задание».

## Пользовательский сценарий
1. Преподаватель → курс → «Создать задание» → заполняет поля, k = 3, дедлайны → задание в списке курса.
2. Попытка с `review_deadline` раньше дедлайна сдачи → ошибка формы.
3. Студент курса → «Мои курсы» → курс → видит задание, дедлайны и фазу «Сдача работ».
4. Студент другого курса по прямой ссылке на задание → 404.

## Технические заметки
- Фаза — метод/свойство модели или функция в `services.py`, без хранения в БД (кроме флага «распределено»).
- Время — всегда aware datetime, `timezone.now()`.
- Новое приложение `apps/assignments`. Модель `Assignment(course, title, description, allowed_formats, max_file_size_mb, kind: individual/team, reviews_per_submission, submission_deadline, review_deadline, allocated_at: null, created_at)` — через `/model`.
- `allowed_formats` — список из фиксированного набора расширений (`pdf`, `docx`, `odt`, `txt`, `zip`, `py`, `ipynb`), ≥ 1; `JSONField` (работает и на SQLite, и на Postgres) + валидация в модели/сервисе. `max_file_size_mb` — 1…50.
- `allocated_at` выставит T-008 (запуск распределения); в T-003 только поле и его влияние на фазу/заморозку.
- Задание выдаётся всему курсу; группы на задание не влияют.
- Поля `datetime-local` в формах — во временной зоне `TIME_ZONE` (Europe/Moscow).
- Шаблоны на базе T-016; права через `apps/accounts/permissions.py`; объекты — из queryset, отфильтрованного по владельцу/записи.
- Вне рамок: рубрика (T-004), пороги детектора халтуры FR-2.5 (T-012), удаление задания.
