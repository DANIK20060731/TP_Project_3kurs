## Цель
Преподаватель описывает, по чему и как оценивается задание.

## Критерии приёмки
- [x] **AC-1** Given задание, When преподаватель добавляет критерии (название, описание, вес > 0) и уровни шкалы каждого критерия (балл, описание), Then рубрика сохраняется. Порядок критериев и уровней задаётся явно.
- [x] **AC-2** (негативный) Критерий без уровней или с повторяющимися баллами → ошибка (`UniqueConstraint(criterion, points)`).
- [x] **AC-3** Функция `max_score(rubric)` возвращает максимальный взвешенный балл; `normalized(scores)` — значение 0..1. Unit-тесты с несколькими весами.
- [x] **AC-4** Рубрику можно скопировать из другого задания того же преподавателя (глубокая копия критериев и уровней).
- [x] **AC-5** (негативный) После начала фазы `review` редактирование рубрики запрещено (сервис бросает ошибку, UI скрывает кнопки).
- [x] **AC-6** Редактор рубрики на HTMX: добавление и удаление критерия без перезагрузки страницы.

## Пользовательский сценарий
1. Преподаватель → задание → «Рубрика» → добавляет 3 критерия по 4 уровня (0–3) → сохраняет → видит итоговую таблицу.

## Технические заметки
- Модели `Rubric(assignment 1:1)`, `Criterion(rubric, title, description, weight, order)`, `ScaleLevel(criterion, points, description)`.
- Подсчёт баллов — чистые функции в `apps/assignments/scoring.py` (без ORM на входе).

## План реализации (2026-11-17)
- Сверка с SPEC FR-2.3: сохраняется только непустая рубрика; у каждого критерия
  непустая шкала. Веса — положительные Decimal, баллы — неотрицательные Decimal,
  максимальный балл каждого критерия положителен. Уровни и критерии имеют явный порядок.
- Нормализация: сумма `вес × выбранный балл`, делённая на сумму
  `вес × максимальный балл`; выбранный балл должен присутствовать в шкале.
- Заморозка FR-2.4: при установленном `allocated_at` и в фазе `closed` изменения
  запрещены; завершение рецензирования не размораживает рубрику.
- Модели — в `models.py`, новая миграция генерируется Django; чистый расчёт —
  `scoring.py`, транзакционные сохранение и копирование с проверкой владельца —
  `rubric_services.py`. Копирование разрешено между заданиями одного преподавателя.
- Редактор — вложенные Django formsets, HTMX-фрагмент для добавления и удаления
  критериев; изменения сохраняются одной транзакцией по общей кнопке сохранения.
  Шкала нового критерия по умолчанию содержит уровни 0–3, её можно изменить.
- Поля весов и баллов — до 8 цифр, из них 2 после запятой. Редактор ограничен
  20 критериями и 10 уровнями каждого: вместе с management-полями и CSRF
  форма укладывается в стандартный лимит Django 1000 POST-полей.
- Просмотр рубрики доступен владельцу и студентам курса через узкие dataclass,
  ссылки на просмотр и редактор размещаются на странице задания.
- Проверки: сначала отдельный test-writer и red-коммит, затем implementer,
  `make check`, независимые code-reviewer/anonymity-auditor, браузерный сценарий,
  `make e2e`, журнал и финальный коммит. Новые зависимости не требуются.
