# T-005: Сдача работ, соавторы, блокировка после дедлайна

- Статус: done
- Владелец: участник 2
- Зависимости: T-003
- Требования: FR-3.1–FR-3.3, NFR-4

## Цель

Студент курса сдаёт файл по заданию и может заменить его до дедлайна. Соавторы видят ту же работу.

## Критерии приёмки

- [x] **AC-1** Given студент записан на курс и дедлайн ещё не наступил, When он сдаёт непустой файл разрешённого формата размером в пределах лимита, Then создаётся работа с уникальным случайным `public_code`. При замене файла код сохраняется, и через приложение доступна последняя версия.
- [x] **AC-2** Given новая или существующая работа, When файл отсутствует, пуст, имеет недопустимый формат или превышает лимит хотя бы на байт, Then форма показывает ошибку, текущие файл и состав авторов сохраняются. Файл ровно на предельный размер допустим.
- [x] **AC-3** Given командное задание, When студент сдаёт файл и вводит точные логины соавторов из курса, Then соавторы видят и могут скачать ту же работу. Форма не раскрывает ростер курса. Неизвестный, внекурсовый, повторный или собственный логин вызывает ошибку. Для индивидуального задания запрос с соавторами отклоняется.
- [x] **AC-4** Given студент уже числится сдающим или соавтором, When его пытаются добавить к другой работе по тому же заданию, Then запрос отклоняется. При одновременных запросах сохраняется не более одного членства для пары «задание, студент».
- [x] **AC-5** Given время равно дедлайну сдачи или позже, When студент пытается сдать файл или изменить существующую работу, Then view и сервис отклоняют изменение. Авторы по-прежнему могут скачать сохранённый файл.
- [x] **AC-6** Given запрос к форме сдачи или адресу скачивания, When его делает гость, Then он перенаправляется на вход. Для чужой и несуществующей сдачи авторизованному студенту возвращается одинаковый 404. POST требует CSRF-токен. Файл хранится под случайным именем в закрытом хранилище и отдаётся вложением с именем на основе `public_code` и расширения. Исходное имя и личные данные автора не передаются в будущий интерфейс рецензента (T-009).

## Пользовательский сценарий

1. Студент открывает командное задание, загружает файл и добавляет соавтора по точному логину.
2. Соавтор открывает задание и скачивает работу. Сдавший студент заменяет файл, после чего по тому же коду скачивается новая версия.
3. После дедлайна сохранённый файл доступен, а отправка изменений отклоняется.

## Технические заметки

- Переиспользовать форматы, лимит и дедлайн из `Assignment`. Клиентский MIME сам по себе не подтверждает формат.
- Проверять права и дедлайн в сервисе и обеспечивать уникальность членства ограничением БД. При сбое замены предыдущая версия должна оставаться доступной.
- В T-005 входит сдача файлом, как в исходном черновике. FR-3.1 допускает файл и/или ссылку.
- Проверить границу дедлайна с freezegun, права по прямым запросам и сценарий команды в браузере.

## Согласованные правила

- Сдавший студент может заменить файл и изменить состав авторов до дедлайна. Соавторы просматривают и скачивают работу.
- Командное задание можно сдать без соавторов.

## Заметки из T-002 (аудит анонимности)
- Соавторов не выбирать из выпадающего списка однокурсников: `apps.courses.services.course_roster` — только для владельца курса. Варианты: ввод точного логина соавтора или приглашение по коду; если список всё же нужен — отдельный сервис и тест, что в HTML студента нет чужих username/email.
- `Enrollment.__str__` выводит username студента — в формах студента задавать `label_from_instance` явно, не выводить `Enrollment` в `{{ }}` и сообщениях.
