## Цель
Реализовать в `apps/allocation` базовый алгоритм распределения для индивидуальных работ и строго доказать его инварианты тестами. Контракт и инварианты — в `apps/allocation/CLAUDE.md`.

## Критерии приёмки
- [x] **AC-1** `allocate(works, reviewers, k, *, forbidden=frozenset(), seed=0)` для индивидуальных работ (каждый автор = рецензент) возвращает словарь `work_id → list[reviewer]`.
- [x] **AC-2** (property) Для случайных `n ∈ [3, 200]` и `k ∈ [1, ⌊(n−1)/2⌋]`: нет самоназначения.
- [x] **AC-3** (property) Нет взаимных пар.
- [x] **AC-4** (property) У каждой работы ровно `k` различных рецензентов, у каждого рецензента ровно `k` работ.
- [x] **AC-5** (property) Детерминизм: одинаковый seed → одинаковый результат; для n ≥ 5 разные seed хотя бы иногда дают разный результат.
- [x] **AC-6** (негативный) `k > ⌊(n−1)/2⌋`, `n < 3`, `k < 1` → `InfeasibleAllocation` с понятным `reason` (на русском, для преподавателя). Примеры: n=2, k=1; n=4, k=2.
- [x] **AC-7** (производительность) n=300, k=3 — меньше 0.5 с (тест с маркером `slow`).
- [x] **AC-8** mypy strict чистый, покрытие модуля ≥ 95%, модуль не импортирует Django (тест проверяет `sys.modules` или AST).

## Технические заметки
- Файлы: `apps/allocation/types.py` (Work, Allocation, InfeasibleAllocation), `apps/allocation/circulant.py`, `apps/allocation/__init__.py` (публичный `allocate`).
- Выбор множества сдвигов `S`: случайное подмножество `{1..⌊(n−1)/2⌋}` размера k по seed — так получается больше вариативности, чем у `{1..k}`.
- Тесты: `tests/property/test_allocation_props.py` (hypothesis, `@settings(max_examples=500)`), `tests/unit/allocation/test_circulant.py` (конкретные примеры и ошибки).
- Обоснование отсутствия взаимности (`s ∈ S ⇒ n−s ∉ S`, так как все `s < n/2`) — докстринг модуля, позже войдёт в записку.

## Решения координатора (приняты при выполнении, на них ссылаются тесты)
1. Результат не зависит от порядка `works` и `reviewers`: порядок строк из БД не гарантирован, а FR-4.4 требует воспроизводимости.
2. Вход вне рамок T-006 (команды, запреты, рецензенты не совпадают с авторами, дубликаты) даёт `InfeasibleAllocation`, а не неверный результат. T-007 снимает это ограничение.
3. `allocate` не меняет глобальное состояние `random` и переданные списки.
