# T-007: Распределение — общий случай (команды, запреты), невыполнимость

- Статус: done
- Владелец: участник 1
- Зависимости: T-006
- Требования: FR-4.2, FR-4.3

## Контракт

У каждой работы уникальный ID и непустой состав авторов. Студент входит
в состав ровно одной работы в задании (T-005). Рецензенты — все авторы,
каждый указан один раз. Пара в `forbidden` состоит из ID рецензента
и ID существующей работы.

## Критерии приёмки

- [x] **AC-1** Для выполнимого задания с командами каждому результату назначается ровно `k`
  разных рецензентов. У каждого рецензента нагрузка равна нижнему или верхнему
  целому от среднего. Нет самоназначений, двух рецензий от одной команды
  к одной работе и взаимных назначений между командами.
- [x] **AC-2** Известные пары из `forbidden` исключаются при поиске, в том числе
  для индивидуальных работ. Неизвестные ID, пересечение команд и несоответствие
  списка рецензентов составу авторов дают понятную ошибку без имён пользователей.
- [x] **AC-3** Property-тесты проверяют инварианты на разных командах и наборах
  запретов. Результат воспроизводится при перестановке входных списков с тем же
  seed. Циркулянтный путь сохраняет прежнее поведение для индивидуальных работ
  без запретов.
- [x] **AC-4** Для невозможных заданий `InfeasibleAllocation.reason` объясняет
  ограничение. Поиск имеет детерминированный предел работы; при достижении
  предела сообщение говорит о незавершённом поиске. Проверяется и случай,
  когда не хватает допустимых рецензентов только у одной работы.
- [x] **AC-5** В SPEC §4 и T-015 зафиксирован тестируемый сценарий: шесть студентов,
  одна команда из двух, пять работ, `k=1`. Пять студентов рецензируют по одной
  работе, ещё один получает нулевую нагрузку.
- [x] **AC-6** В ADR 0004 — сравнение двух алгоритмов, замеры времени и баланса.
  Ядро остаётся на стандартной библиотеке, с покрытием ≥ 95%.

## Заметки из ревью T-006
- В T-006 отказ для любых команд и запретов был временным ограничением. В T-007 эти случаи проверяются как поддерживаемые, а проверки ошибочных составов и неизвестных ID сохранены.
- В бенчмарк добавить сравнение анонимности: у циркулянта сдвиги коммутируют, поэтому известные пары помогают вывести другие (из `x→b`, `x→c`, `b→d` часто следует `c→d`).
- Для `k=1` возможны короткие циклы: при n=30 и сдвиге 10 есть циклы длины 3 (A→B, B→C, C→A).

## Решения человека (2026-11-04)
- Структурный риск циркулянта принят для курсовой: алгоритм не меняем, риск описываем в записке и в ADR 0004. Без чужих назначений студент пары не вычислит; риск возникает только при сговоре.
- Сценарий 2 в SPEC §4 исправляется в этой задаче: когда появится поддержка команд, подобрать выполнимые числа, проверить их тестом и обновить SPEC и T-015.
