## Критерии приёмки (черновик)
- [ ] **AC-1** Преподаватель в фазе `allocation` нажимает «Распределить» → создаются `AllocationRun` (seed, k, алгоритм) и `ReviewAssignment` атомарно.
- [ ] **AC-2** (негативный) Повторный запуск запрещён; запуск до дедлайна сдачи запрещён.
- [ ] **AC-3** (негативный) Невыполнимость — сообщение преподавателю с причиной, в БД ничего не создано.
- [ ] **AC-4** Ручное переназначение рецензии с проверкой инвариантов.
- [ ] **AC-5** (анонимность) Студент видит свои назначения только по `public_code`.
- [ ] **AC-6** (анонимность) `AllocationRun.seed` берётся из `secrets.randbits(63)` и всегда передаётся в `allocate` явно. Его видит только преподаватель, в логи и ответы студентам он не попадает.

## Заметки из аудита анонимности T-006
- `seed` — ключ ко всем парам: зная состав авторов, `k` и `seed`, можно вычислить весь граф. Значение по умолчанию `seed=0` в сервисе использовать нельзя.
- `ReviewAssignment` создавать в порядке, перемешанном секретным значением: рецензенты в результате `allocate` отсортированы, поэтому номер рецензии по pk выдал бы алфавитный ранг рецензента.
- `Work.id` равен `public_code`, а не pk: он попадает в `InfeasibleAllocation.reason`. Сам `reason` показывается только преподавателю.
- Объект `Allocation` не логировать: в сервисах логировать только id запуска и счётчики.
