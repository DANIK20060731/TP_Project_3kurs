# T-008: Запуск распределения: AllocationRun, ReviewAssignment

- Статус: done
- Владелец: участник 1
- Зависимости: T-005, T-007
- Требования: FR-4.1–FR-4.5, FR-5.1, NFR-1

## Критерии приёмки

- [x] **AC-1** Владелец задания с сохранённой рубрикой может запустить распределение
  с его страницы после дедлайна сдачи и до дедлайна рецензий. Успех атомарно
  сохраняет один `AllocationRun`, все `ReviewAssignment` и `Assignment.allocated_at`.
  Запуск содержит `seed`, `k`, имя алгоритма и время. Назначения получают только
  авторы сданных работ, включая соавторов.
- [x] **AC-2** Повторный, ранний и поздний запуск отклоняются. При параллельных
  запросах запускается ровно одно распределение. Гость перенаправляется на вход,
  студент и чужой преподаватель получают отказ. Запуск и переназначение
  принимают только POST с CSRF-защитой.
- [x] **AC-3** Невыполнимое распределение и отсутствие рубрики объясняются владельцу.
  Отказ и ошибка записи оставляют БД без запуска и частичных изменений.
- [x] **AC-4** Владелец в фазе рецензирования выбирает нового рецензента из авторов
  задания. Переназначение сохраняется атомарно при соблюдении FR-4.2. Проверяются
  самоназначение, взаимность, повтор рецензента или команды и баланс по всем
  авторам. После дедлайна назначения доступны владельцу для просмотра.
- [x] **AC-5** На странице задания студент видит только свои коды `public_code`,
  без данных авторов, чужих назначений, PK рецензий и сведений о запуске.
  Владелец может открыть отдельную страницу со сводкой и назначениями.
- [x] **AC-6** Сервис явно передаёт `seed` из `secrets.randbits(63)` в `allocate`
  и сохраняет его в запуске. Студенческий ответ и журналы его не содержат.
  Порядок записей при создании перемешивается независимым секретным источником.

## Пользовательский сценарий

Преподаватель открывает задание после закрытия сдачи, нажимает «Распределить»
и видит сохранённые назначения. Студент открывает то же задание и видит коды
своих работ для рецензирования. Преподаватель может открыть назначения и
переназначить рецензию, соблюдая ограничения.

## Заметки из аудита анонимности T-006
- `seed` — ключ ко всем парам: зная состав авторов, `k` и `seed`, можно вычислить весь граф. Значение по умолчанию `seed=0` в сервисе использовать нельзя.
- `ReviewAssignment` создавать в порядке, перемешанном секретным значением: рецензенты в результате `allocate` отсортированы, поэтому номер рецензии по pk выдал бы алфавитный ранг рецензента.
- `Work.id` равен `public_code`, а не pk: он попадает в `InfeasibleAllocation.reason`. Сам `reason` показывается только преподавателю.
- Объект `Allocation` не логировать: в сервисах логировать только id запуска и счётчики.
