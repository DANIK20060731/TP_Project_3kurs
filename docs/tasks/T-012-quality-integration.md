# T-012: Флаги халтуры в БД и в интерфейсе преподавателя

- Статус: done
- Владелец: участник 1
- Зависимости: T-009, T-011
- Требования: FR-2.5, FR-6.1, FR-6.2

## Критерии приёмки

- [x] **AC-1** При отправке и изменении отправленной рецензии детекторы
  пересчитывают флаги в пределах её задания. Черновики и аннулированные
  рецензии исключены. Повторный прогон обновляет текущие флаги без дублей.
  Команда `scan_review_quality` прогоняет детекторы после дедлайна.
- [x] **AC-2** Владелец может настроить минимум значимых слов, порог сходства
  и минимум секунд на странице задания. Некорректные значения отклоняются
  с ошибками формы. По умолчанию действуют пороги T-011.
- [x] **AC-3** Владелец задания видит флаги с причинами и текстом рецензии,
  может отклонить флаг или аннулировать рецензию. Отклонение сохраняется
  при повторном прогоне той же версии. Аннулированная рецензия не входит
  в отзывы автора и автоматический итог. Ручной итог сохраняется.
- [x] **AC-4** Студент и преподаватель чужого курса получают одинаковый
  отказ на маршрутах качества. Действия защищены CSRF. Студенты не видят
  флаги, причины, сведения о совпадениях и внутренние данные проверок.

## Пользовательский сценарий

После отправки короткой рецензии преподаватель открывает «Качество рецензий»
со страницы задания. Он видит текущие пороги, рецензию и причину флага, затем
отклоняет флаг или аннулирует рецензию.

## Требования из аудита анонимности T-011
1. В `ReviewText.review_id` передавать случайный код рецензии (нужно поле вроде `Review.public_code`), а не pk, username или `Submission.public_code`: этот id попадает в `Flag.reason`. `QualityFlag` хранит FK на `Review`.
2. В `ReviewText.reviewer_id` передавать непрозрачное значение, а не username или email.
3. Детекторы запускать только в пределах одного задания, иначе `reason` покажет рецензию чужого курса.
4. Флаги и действия с ними доступны только преподавателю этого курса. Студент и преподаватель чужого курса получают одинаковый отказ на всех URL, включая HTMX-фрагменты. В Django admin показ ограничить так же или не регистрировать модель.
5. `reason`, `score`, `detector` и `ReviewText` не попадают в логи, `messages`, письма, тексты ошибок, CSV и `__str__` модели. В логи — только счётчики и имя детектора.
6. Контекст шаблонов студента не содержит `QualityFlag` и его полей, `data-*` атрибутов и признака «есть флаг».
7. Аннулирование рецензии не раскрывает автору причину и партнёра, рецензенту не показываются `reason` и `score`. Автор видит только нейтральное состояние. Отклонённые флаги студентам тоже не видны.
8. Обязательные тесты через тест-клиент: ответы студента не содержат маркерных username, `reason`, кода рецензии-партнёра и `score`; преподаватель чужого курса получает отказ; записи `caplog` не содержат `reviewer_id` и текста комментария. Маркеры — уникальные строки, а не числа.
9. `reason` выводится через автоэкранирование шаблона, без `|safe`.
10. `QualityConfig` бросает `ValueError` на неверных порогах: форма настроек задания (AC-2) должна проверять диапазон сама и показывать понятную ошибку.

## Решения реализации

- Переход ко второй рецензии по флагу копипаста отложен. Используется текущий контракт T-011 и публичный код совпавшей рецензии в текстовой причине.
- Время рецензирования — интервал от первого открытия формы до первой отправки по серверным отметкам. Для ранее отправленных рецензий без отметки открытия детектор времени пропускается.
- Форма рецензии уже содержит подсказку об анонимности свободного текста из T-010.
