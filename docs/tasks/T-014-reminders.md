# T-014: Напоминания о дедлайнах

- Статус: done
- Владелец: участник 2
- Зависимости: T-005, T-008, T-009, T-012
- Требования: FR-8.1–FR-8.3

## Критерии приёмки
- [x] **AC-1 (сдача)** Команда `send_reminders` отправляет письма за 24 ч и за 2 ч до дедлайна студентам курса без сдачи. Сдавшие и соавторы исключаются.
- [x] **AC-1 (рецензирование)** Напоминания за 24 ч и за 2 ч студентам хотя бы с одной неотправленной рецензией.
- [x] **AC-2** Идемпотентность: журнал `ReminderLog`, повторный запуск не шлёт дубли (тест с freezegun).
- [x] **AC-3** Письма о назначении рецензий и о получении рецензий.
- [x] **AC-4** (анонимность) В тексте писем нет имён авторов и рецензентов.
- [x] **AC-5** [ADR о запуске через cron](../adr/0005-reminder-scheduling.md).

## Запуск и поведение

После `make migrate` команда `uv run python manage.py send_reminders` использует почтовый backend из настроек Django. В dev по умолчанию письма выводятся в консоль.

- Для обоих дедлайнов 24-часовое письмо отправляется в интервале от 24 до 2 часов, исключая последние 2 часа. В последние 2 часа отправляется 2-часовое письмо. С дедлайна напоминания прекращаются.
- Письмо о назначении отправляется при очередном запуске команды до дедлайна рецензирования. С дедлайна автор и соавторы получают письмо, если по их работе есть хотя бы одна отправленная неаннулированная рецензия. Это соответствует сроку открытия отзывов в T-010. При развёртывании включать cron после выхода T-010, чтобы получатели могли открыть отзывы на сайте.
- Получатели — активные студенты курса с email. Письма содержат курс и задание, а также применимый дедлайн в часовом поясе проекта. Имена, коды работ и содержимое рецензий в письма не включаются.
- Каждый тип письма отправляется студенту один раз на задание, в том числе при переносе дедлайна. Для напоминаний за 24 и 2 часа ведутся отдельные записи. При ошибке доставки запись откатывается, а команда завершается с ненулевым статусом после обработки остальных получателей.
