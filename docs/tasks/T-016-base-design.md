# T-016: Базовый дизайн интерфейса

- Статус: todo
- Владелец: участник 2
- Зависимости: T-001
- Требования: NFR-5

## Цель
Единый внешний вид и адаптивная вёрстка до появления новых экранов: общий шаблон, навигация и стили типовых элементов, которые следующие задачи используют готовыми.

## Критерии приёмки
- [ ] **AC-1** Given любая страница на `base.html`, When она открывается, Then в ней подключён локальный файл `static/css/app.css`, и `finders.find("css/app.css")` его находит.
- [ ] **AC-2** Given гость, When он открывает главную, Then в шапке есть ссылки «Вход» и «Регистрация», а кнопки «Выйти» нет.
- [ ] **AC-3** Given вошедший пользователь, When он открывает главную, Then в шапке видны его имя, роль на русском («Студент» или «Преподаватель») и кнопка «Выйти», отправляющая POST с CSRF-токеном, а ссылок «Вход» и «Регистрация» нет.
- [ ] **AC-4** Given ширина экрана 375 px, When открываются главная, вход и регистрация, Then горизонтальной прокрутки нет (`scrollWidth <= clientWidth`), а поля и кнопки форм помещаются в экран.
- [ ] **AC-5** Given ширина экрана 1280 px, When открывается главная, Then содержимое ограничено по ширине и выровнено по центру, а шапка показана в одну строку.
- [ ] **AC-6** (негативный) Given неверные данные на странице входа или регистрации, When форма отправлена, Then ошибка показана элементом с `role="alert"`, а введённое имя пользователя сохраняется.
- [ ] **AC-7** (негативный) Given студент на странице только для преподавателя или любой пользователь на несуществующем адресе, When страница открывается, Then ответ 403 или 404 показан оформленной страницей на русском со ссылкой на главную, и техническая информация не раскрывается.
- [ ] **AC-8** (анонимность) Given страница с шапкой, When её открывает пользователь, Then в шапке только данные его самого, а в шаблоны не добавлены имена или id других пользователей.
- [ ] **AC-9** Given существующие тесты T-001, When выполняются `make check` и `make e2e`, Then они проходят без изменений.

## Пользовательский сценарий
1. Гость на телефоне открывает главную → видит шапку без горизонтальной прокрутки → переходит на «Регистрация» → заполняет форму.
2. Попадает на главную и видит в шапке своё имя и роль → «Выйти» → снова гость.
3. Открывает несуществующий адрес → видит страницу 404 → возвращается на главную по ссылке.

## Технические заметки
- Файлы: `templates/base.html`, `static/css/app.css`, `templates/403.html`, `templates/404.html`, шаблоны `accounts` и `core/home.html`.
- Свой небольшой CSS без новых зависимостей и CDN: системные шрифты, один акцентный цвет, переменные в `:root`, подход «сначала мобильный». Тёмная тема вне рамок задачи.
- В начале `app.css` перечислить классы и элементы для следующих задач: формы, кнопки (основная и второстепенная), таблица, карточка, сообщение, пустой список.
- Стили только в `app.css`: без `style="…"` в шаблонах. Оформлять семантические элементы (`header`, `nav`, `main`, `form`, `table`), чтобы следующим задачам требовалось меньше классов.
- Ссылки «Вход», «Регистрация» и кнопку «Выйти» перенести с главной в шапку, а не дублировать: e2e-тесты T-001 ищут их по роли и имени, и два одинаковых элемента их сломают.
- Подключить `django.contrib.messages` в `base.html`, чтобы сообщения следующих задач (например, «Вы уже записаны» в T-002) показывались единообразно.
- Тесты: integration для AC-1–AC-3 и AC-6–AC-8; e2e с `page.set_viewport_size` для AC-4 и AC-5. Анонимность проверяет anonymity-auditor.

## Открытые вопросы
- Как отдавать статику в проде? В `config/settings/prod.py` при `DEBUG = False` CSS сам не раздастся, а способа развёртывания в проекте пока нет. Если защита пройдёт на локальном запуске, вопрос можно закрыть без изменений. Если на сервере, понадобится WhiteNoise (новая зависимость, нужно согласие) или nginx. На выполнение задачи не влияет: в разработке и тестах статика работает.
