# T-018: Наполненная главная — о платформе для гостя, курсы и ближайшие дедлайны

- Статус: in-progress
- Владелец: участник 2
- Зависимости: T-017 (стиль, PR #10; ветка `feat/T-018-home` создана от `feat/T-017-visual-style`).
- Требования: NFR-5, NFR-1 (анонимность), NFR-4 (без IDOR). Наполненная главная взята из описания человека от 2026-11-05. SPEC не меняем (решение 3).
- Происхождение: критерии AC-13–AC-22 из `docs/tasks/T-017-visual-style.md`, здесь они перенумерованы в AC-1–AC-10. Дизайн — `docs/design/T-017-editorial-plan.md` §8.

## Цель
Главная перестаёт быть пустой:
- гость видит внятный экран о платформе: как работает peer-review в 3 шага, и кнопки-призывы;
- вошедший видит свои курсы карточками и «Ближайшие дедлайны».

Всё в стиле «Редакторская правка».

## Решения (человек, 2026-11-05)
1. **Ближайшие дедлайны — по фазе.**
   - Для каждого задания показывается дедлайн текущей фазы:
     - «Сдача работ» → дедлайн сдачи (вид «сдача работ»);
     - «Распределение» и «Рецензирование» → дедлайн рецензий (вид «рецензии»);
     - «Завершено» → ничего.
   - Только будущие дедлайны: дедлайн строго больше текущего момента, просроченные не показываются. Границы совпадают с `Assignment.phase`.
   - Не больше **5** элементов, по возрастанию даты, при равенстве — по `pk` задания.
   - Студенту — задания курсов, на которые он записан. Преподавателю — задания его курсов.
   - Сдачу работы не учитываем: модели `Submission` пока нет (T-005).
2. **Подписи без подстрок из e2e.**
   - Кнопки гостя: «Войти» → `/accounts/login/`, «Создать учётную запись» → `/accounts/signup/`.
   - Пустые состояния: «Ввести код приглашения» → `/courses/enroll/` (студент), «Новый курс» → `/courses/create/` (преподаватель).
3. **Сервис** — в `apps/courses/services.py` (рядом с `AssignmentRow` и `course_assignment_rows`). Он возвращает frozen dataclass без ORM-объектов. `core.views.home` только вызывает сервис. SPEC не меняем.

## Критерии приёмки
- [ ] **AC-1** Given гость, When он открывает `/`, Then на странице ровно один `h1`, и он содержит «peer-review» (smoke-тест и T-016). Под ним блок «Как это работает» — `ol` ровно из 3 `li` по SPEC: сдать работу до дедлайна → анонимно отрецензировать работы однокурсников по рубрике → получить рецензии и итоговую оценку. Также есть 2 призыва к действию со ссылками на `/accounts/login/` и `/accounts/signup/`.
- [ ] **AC-2** (негативный, не ломать e2e T-001/T-016) Given гость на `/`, When тест ищет ссылки, Then на всей странице ровно одна ссылка с текстом, точно равным «Вход», и одна — с «Регистрация» (обе в шапке). Нет второй ссылки, доступное имя которой содержит «вход» или «регистрация» без учёта регистра: Playwright ищет `get_by_role("link", name="Регистрация")` по подстроке на всей странице. Подписи кнопок-призывов — «Войти» и «Создать учётную запись» (решение 2).
- [ ] **AC-3** Given вошедший студент, записанный на 2 курса, When он открывает `/`, Then в `main` видны оба курса. Название каждого — ссылка с точным href `/courses/<pk>/`, ссылок на `/courses/<pk>/manage/` нет. Given преподаватель с 2 своими курсами, Then видны оба, ссылки ведут на `/courses/<pk>/manage/`, а чужих курсов нет.
- [ ] **AC-4** Given вошедший студент, When он открывает `/`, Then там есть блок «Ближайшие дедлайны». В каждом элементе: название задания (ссылка `/assignments/<pk>/`), название курса, вид дедлайна («сдача работ» или «рецензии»), дата и время по `TIME_ZONE` в формате `d.m.Y H:i` внутри `<time datetime="…">` и бейдж фазы. Элементы отсортированы по возрастанию даты, при равенстве — по `pk` задания. Состав элементов — по решению 1. Тест фиксирует выбранное правило через freezegun на границах: дедлайн ровно сейчас, за 1 секунду до и через 1 секунду после. Граница совпадает с вычислением фазы в `Assignment.phase` из T-003.
- [ ] **AC-5** (негативный, права) Given студент записан на курс A и не записан на курс B, у обоих курсов есть задания с будущими дедлайнами, When он открывает `/`, Then заданий и названия курса B нет во всём HTML. Given преподаватель, Then нет заданий чужих курсов. Given студент записан на курс без заданий, Then курс виден в списке курсов, а в дедлайнах его нет.
- [ ] **AC-6** (анонимность, узкий контекст) Given студент на `/`, When рендерится главная, Then в контекст шаблона не попадают ORM-объекты `Course`, `Assignment` и `Enrollment`, только dataclass-строки из сервиса. Тест перебирает `response.context` и проверяет типы значений. Во всём HTML нет username и email однокурсников, username владельца курса и `invite_code`.
- [ ] **AC-7** (пустые состояния) Given студент без курсов, When он открывает `/`, Then вместо списка курсов показано пустое состояние `.empty` с подсказкой, как записаться. Given студент с курсами, но без предстоящих дедлайнов, Then в блоке дедлайнов показано `.empty` «Ближайших дедлайнов нет». То же для преподавателя без курсов и без заданий.
- [ ] **AC-8** (негативный, не ломать e2e T-002/T-003) Given вошедший студент или преподаватель, в том числе без курсов, When открыта `/`, Then в `main` нет ссылок, доступное имя которых без учёта регистра содержит «мои курсы», «записаться» или «создать курс». e2e кликают `get_by_role("link", name="Мои курсы"|"Записаться"|"Создать курс")` на главной сразу после входа, а Playwright ищет по подстроке, поэтому дубль даёт ошибку strict mode. Подписи ссылок пустого состояния — «Ввести код приглашения» (студент) и «Новый курс» (преподаватель) (решение 2). Фразы «Вы вошли как» в `main` нет.
- [ ] **AC-9** (производительность) Given студент на 5 курсах с 10 заданиями, When открыта `/`, Then число SQL-запросов не больше, чем для студента на 1 курсе с 1 заданием (`django_assert_max_num_queries`, без N+1). То же для преподавателя.
- [ ] **AC-10** Given `core/home.html`, When его рендерит view без контекста главной (тестовые view `t/message/` и `t/teacher-only/` в `tests/integration/core/test_base_design.py`), Then шаблон рендерится без ошибок: блоки курсов и дедлайнов скрыты или пусты.

## Пользовательский сценарий (для e2e)
1. Гость на 375 px открывает главную: словесный знак, 3 шага peer-review и 2 кнопки-призыва. Горизонтальной прокрутки нет. По кнопке «Войти» попадает на страницу входа.
2. `student01` входит. На главной курс «Технологии программирования» показан карточкой, в «Ближайших дедлайнах» — дедлайны демо-заданий с бейджами фаз. В шапке ни одна ссылка не подсвечена.
3. `teacher` входит. На главной его курс (карточка ведёт на manage) и дедлайны его заданий.

## Технические заметки
- **Сервис** `home_page(user) -> HomePage`:
  - поля: `courses: tuple[HomeCourse, ...]` (`pk`, `title`, `url_name`) и `deadlines: tuple[HomeDeadline, ...]` (`assignment_pk`, `assignment_title`, `course_title`, `kind`, `kind_label`, `deadline`, `phase`, `phase_label`);
  - без username, email, `invite_code` и ORM-объектов;
  - запросов — фиксированное число: `select_related` / один запрос по заданиям (AC-9).
- **Шаблон.** `core/home.html` рендерится и без контекста главной: блоки внутри `{% if page %}` (AC-10). Классы из плана §8: `ol.steps`, `.card--course`, `.stretched-link`, `ol.deadlines`, `.badge-phase--*`.
- **Тесты, которые нельзя ломать,** — таблица «На что опираются существующие тесты» в T-017. Главное:
  - ровно один `h1` с «peer-review» у гостя;
  - ровно одна ссылка «Вход» и одна «Регистрация» на всей странице гостя;
  - в `main` вошедшего нет ссылок с «мои курсы», «записаться», «создать курс».
- Время дедлайнов — по `TIME_ZONE`, формат `d.m.Y H:i` внутри `<time datetime>`. Стили только в `app.css`.
