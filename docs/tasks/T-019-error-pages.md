# T-019 · Страницы ошибок CSRF и выхода

- Статус: done
- Владелец: участник 2
- Зависимости: T-017
- Требования: NFR-4, NFR-5

## Цель

После отказа CSRF или прямого открытия адреса выхода пользователь видит оформленную страницу с понятным способом продолжить работу.

## Критерии приёмки

- [x] **AC-1** Given `DEBUG=False`, When сервер отклоняет POST без CSRF-токена, Then ответ содержит русскоязычную страницу на `base.html`, код 403 и ссылку на главную. В HTML отсутствуют техническая причина отказа и данные отправленной формы.
- [x] **AC-2** Given активная сессия, When пользователь открывает `GET /accounts/logout/`, Then ответ содержит оформленную страницу 405 с заголовком `Allow: POST`, а сессия остаётся активной.
- [x] **AC-3** Given активная сессия, When пользователь отправляет форму выхода с действующим CSRF-токеном, Then сессия завершается и браузер переходит на главную.

## Согласованное решение

Использовать системный стек шрифтов по решению из T-017.

## Пользовательский сценарий

Пользователь входит, открывает адрес выхода и видит страницу 405. Затем он выходит кнопкой в шапке.

## Технические заметки

- Django автоматически выбирает шаблон `403_csrf.html` при отказе CSRF.
- Выход принимает только POST. Остальные методы, включая OPTIONS, получают оформленный 405 с `Allow: POST`.
