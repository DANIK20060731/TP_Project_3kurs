# T-020: Ручная мини-защита автора

- Статус: todo
- Владелец (предложение): участник 2
- Зависимости: T-005, T-009, T-010
- Требования: [проект FR-9.1, FR-9.2, FR-9.4](../SPEC-proposal-mini-defense.md), NFR-1, NFR-4

## Цель

Дать владельцу курса возможность провести устную проверку конкретного автора без внешнего сервиса.

## Критерии приёмки

- [ ] **AC-1** Given работа с авторами и действующими отправленными рецензиями, When владелец открывает её с момента дедлайна рецензий, Then видит работу и оценки, выбирает автора и создаёт карточку. За мгновение до дедлайна создание отклоняется сервером.
- [ ] **AC-2** Given карточка в подготовке, When владелец сохраняет ручные вопросы, Then при повторном просмотре видит тот же набор, источники и авторство действий. При начале набор фиксируется, попытка изменить его отклоняется.
- [ ] **AC-3** Given проведение, When владелец отмечает заданные вопросы и сохраняет результаты («самостоятельно», «с подсказкой», «пока не объяснил») и короткие комментарии, Then защита завершается только при хотя бы одном заданном вопросе с результатами по всем заданным. Незаданные остаются без результата. Завершённая карточка открывается для просмотра.
- [ ] **AC-4** Given командная работа, When защищается один соавтор, Then результат относится только к нему. Фаза задания и итоговая оценка до и после совпадают.
- [ ] **AC-5** Given студент, чужой преподаватель, POST без CSRF или GET на изменение, When запрашивают карточку или изменение, Then доступ или запись отклоняются, служебные данные не раскрываются.

## Пользовательский сценарий (e2e)

Владелец открывает командную работу после дедлайна, выбирает соавтора, сохраняет два вопроса, начинает защиту, отмечает один заданным и завершает после фиксации результата. При повторном просмотре результат относится к выбранному студенту, второй вопрос остаётся незаданным.

## Технические заметки

Вводит начальную схему `apps/defenses`. См. [архитектуру](../ARCHITECTURE.md#проверка-понимания-проект-расширения) и [ADR](../adr/0006-defense-lifecycle.md). Для T-022/T-023 вопрос хранит происхождение, связь с предложением и признак правки. Транзакционные проверки переходов и объектных прав покрываются интеграционными тестами.
