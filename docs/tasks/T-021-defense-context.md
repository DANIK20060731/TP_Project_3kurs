# T-021: Извлечение текста и контекст проверки

- Статус: todo
- Владелец (предложение): участник 1
- Зависимости: T-005, T-009, T-010
- Требования: [проект FR-9.3, FR-9.6](../SPEC-proposal-mini-defense.md), NFR-1, NFR-4

## Цель

Подготовить ограниченный контекст одной работы с проверяемыми ссылками на источники.

## Критерии приёмки

- [ ] **AC-1** Given небольшой PDF с текстовым слоем, DOCX или UTF-8 TXT в закрытом хранилище, When сервис читает его, Then оригинал сохраняется и фрагменты имеют устойчивые ключи и координаты страницы, абзаца или строк соответственно.
- [ ] **AC-2** Given скан без текста, неподдерживаемый формат, повреждение, превышение лимита или недоступность файла, When запрашивают извлечение, Then получается различимое состояние по контракту. Ручная защита остаётся доступна.
- [ ] **AC-3** Given черновики, аннулированные рецензии и другая работа того же задания, When собирается контекст, Then он содержит только задание, рубрику, текст выбранной работы и её действующие отправленные рецензии с оценками и комментариями. Снимок фиксирует идентификатор содержимого и версии рецензий.
- [ ] **AC-4** Given чужой объект либо материалы с титульными страницами и возможными персональными данными, When готовят внешний пакет, Then чужой доступ отклоняется, прямые идентификаторы из БД не добавляются, материалы обрабатываются по утверждённой политике. При невозможности применить её отправка блокируется. Сырой текст отсутствует в обычных логах.

## Технические заметки

Парсеры отделены от UI; контракт статусов, ключей и снимков описан в [архитектуре](../ARCHITECTURE.md#контракты-контекста-и-предложения). Нужны небольшие реальные фикстуры трёх форматов и проверки недоступного файла, лимитов, стабильности ключей и изоляции работ. OCR, архивы и другие форматы вне первой версии.

## Открытые вопросы

- Согласовать библиотеки, пределы байтов, страниц, фрагментов и времени, обработку титульников и персональных сведений, срок хранения и порядок удаления снимков.
