# T-022: Генерация вопросов автору

- Статус: todo
- Владелец (предложение): участник 1
- Зависимости: T-020, T-021
- Требования: [проект FR-9.3, FR-9.6](../SPEC-proposal-mini-defense.md), NFR-4

## Цель

Подготовить для преподавателя вопросы на объяснение решения, ограничений, проверки результата и изменения условий.

## Критерии приёмки

- [ ] **AC-1** Given подготовленный снимок, When поставщик отвечает по контракту, Then попытка хранит 5–10 предложений с вопросом, основанием, целью и ориентирами. Записаны снимок, инициатор, поставщик, модель, версия инструкции и состояние.
- [ ] **AC-2** Given неверная структура, отсутствующий ключ источника или цитата вне фрагмента, When сервис проверяет ответ, Then попытка получает ошибку и предложения не доступны для утверждения. Инструкции из материалов передаются как данные и не меняют задачу.
- [ ] **AC-3** Given отсутствующий ключ, тайм-аут, сбой или превышение лимита, When преподаватель запускает генерацию, Then получает понятное состояние и может продолжить вручную. Повторы выполняются явно и не зацикливаются.
- [ ] **AC-4** Given утверждённые и ручные вопросы, When владелец повторяет запрос, Then создаётся отдельная попытка, утверждённый набор сохраняется. Чужой пользователь запускать или читать попытки не может.

## Технические заметки

Использовать контракт [предложения и попытки](../ARCHITECTURE.md#контракты-контекста-и-предложения). Проверка основания техническая, пригодность оценивает преподаватель. Автотесты используют подставного поставщика; проверку реального API описать после настройки ключа.

## Открытые вопросы

- До реализации согласовать поставщика, модель, бюджет, лимиты, зависимости и способ запуска. Выбранную интеграцию оформить ADR.
