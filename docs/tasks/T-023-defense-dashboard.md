# T-023: Подготовка вопросов и результаты на дашборде

- Статус: todo
- Владелец (предложение): участник 2
- Зависимости: T-020, T-022, T-013
- Требования: [проект FR-9.2–FR-9.4](../SPEC-proposal-mini-defense.md), NFR-1, NFR-4, NFR-5

## Цель

Связать предложения ИИ с экраном подготовки и показать статус проверки рядом с итогом работы.

## Критерии приёмки

- [ ] **AC-1** Given подготовка защиты, When преподаватель запускает генерацию, Then видит ожидание и затем готовые предложения с основанием и ориентирами либо понятную ошибку с доступным ручным режимом.
- [ ] **AC-2** Given предложения, When владелец выбирает, редактирует и утверждает вопросы, Then только выбранные попадают в набор, сохраняются исходное основание и признак правки. Ручной вопрос может быть без основания. Утверждение само по себе не отмечает вопрос заданным.
- [ ] **AC-3** Given ручные и утверждённые вопросы, When повторная генерация успешна или завершается ошибкой, Then ранее подготовленный набор доступен и неизменён.
- [ ] **AC-4** Given сохранённая защита, When владелец открывает дашборд, Then видит статус и переход к карточке отдельно от оценки отчёта. Студент и чужой преподаватель не получают этих данных по прямым URL. На узком экране элементы выбора и статусы доступны.

## Пользовательский сценарий (e2e)

Владелец запускает генерацию с подставным сервисом, читает основание, правит и утверждает один вопрос, проводит защиту и возвращается на дашборд. Отдельный сценарий проверяет ошибку, повтор и сохранение ручного вопроса.

## Технические заметки

Использовать существующие шаблоны и стили. Статус и переход получает дашборд из сервиса защиты; расчёт оценки остаётся в T-010/T-013.

## Открытые вопросы

- Согласовать представление нескольких карточек на одну работу, в том числе для разных соавторов.
