# T-024: Проверка понимания рецензента

- Статус: todo
- Владелец (предложение): участник 1
- Зависимости: T-012, T-023
- Требования: [проект FR-9.4–FR-9.6](../SPEC-proposal-mini-defense.md), NFR-1, NFR-4

## Цель

Попросить рецензента обосновать конкретную оценку или замечание к работе.

## Критерии приёмки

- [ ] **AC-1** Given конкретная отправленная действующая рецензия, When владелец создаёт защиту рецензента, Then карточка связывается именно с этой рецензией и её автором. Предложения опираются на оценку, комментарий по критерию и фрагмент соответствующей работы.
- [ ] **AC-2** Given флаг качества, When владелец открывает страницу модерации, Then может перейти к созданию проверки этой рецензии. Прямой сценарий для рецензии без флага тоже работает. Черновик, чужая рецензия или несовместимые связи отклоняются.
- [ ] **AC-3** Given результат проверки рецензента, When преподаватель сохраняет его, Then результат автора, состояние рецензии, флаги и итог работы не меняются. Флаг служит поводом для проверки, а не доказательством.
- [ ] **AC-4** Given студент или чужой преподаватель, When он обращается к маршруту защиты, Then личности, замечания, служебные флаги и результаты не раскрываются.

## Пользовательский сценарий (e2e)

Владелец переходит от флага к защите, выбирает вопрос об обосновании замечания, проводит проверку и видит отдельные результаты автора и рецензента. Повторить создание для другой отправленной рецензии без флага.

## Технические заметки

Расширить модуль T-020 после обновления ветки. Детекторы и аннулирование остаются в T-012. Использовать переход через URL без циклического импорта.

## Открытые вопросы

- Уточнить доступность старой карточки и возможность продолжения проверки после аннулирования её исходной рецензии.
